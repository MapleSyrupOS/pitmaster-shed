# adr-index

Writes `INDEX.md`, one table row per architecture decision record (ADR), from the ADRs themselves. Every cell
comes from the ADR file, so the table cannot drift from the records. With `--check` it writes nothing and fails
when the index is missing or stale, which makes it a CI step or a pre-commit hook.

Python 3.8 or newer, standard library only. macOS, Linux, Windows.

## Usage

```
python3 adr-index.py [--root DIR] [--dir PATH] [--check]
python3 adr-index.py --self-test
```

| Option | Meaning |
|--------|---------|
| `--root DIR` | The repository root. Default: the current directory. The tool never looks in a folder above it. |
| `--dir PATH` | The decisions folder, relative to the root. Default: the first of `docs/decisions`, `docs/adr`, `docs/adrs`, `doc/adr`, `doc/decisions`, `adr`, `decisions` that exists. |
| `--check` | Write nothing. Exit 1 if `INDEX.md` is missing or differs from what would be written. |
| `--self-test` | Run the built-in cases, print `PASS` or `FAIL` for each, then a verdict line. Exits non-zero on any failure. |

## The table

An ADR is a Markdown file in the decisions folder named like `ADR-001-some-slug.md` or `0001-some-slug.md`.
Four formats are read; the first is the one the table is built for.

| Format | Where the cells come from |
|--------|---------------------------|
| ADR+ | The YAML header at the top of the file: `kind`, `status` and `built`. |
| Bold lines | `**Status:**` and `**Built:**` under the title (the ADR+ header before it moved to YAML). Kind shows `—`. |
| MADR | `status:` in the front matter, or a `## Status` section beside MADR's option headings. Kind and Built show `—`. |
| Nygard | The line under `## Status`. Kind and Built show `—`. |

The Decision cell is the title without its `ADR-001 —` prefix. The Status cell is one of the seven ADR+ words
(proposed, provisional, accepted, partially accepted, superseded, withdrawn, rejected); an older verdict such as
"Ratified" is mapped to its word. A `|` in a title is escaped. Rows are sorted by number. Files that are not ADRs
(a `README.md`, a template) are ignored.

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | The index was written, or (with `--check`) it is current. |
| 1 | With `--check`: `INDEX.md` is missing or stale. Nothing was written. |
| 2 | No decisions folder was found. Nothing was written. |

## Example

```
$ python3 adr-index.py
adr-index: wrote docs/decisions/INDEX.md (2 ADRs)
$ python3 adr-index.py --check
adr-index: docs/decisions/INDEX.md is current
$ echo "edit an ADR's status, then:" && python3 adr-index.py --check
adr-index: docs/decisions/INDEX.md is stale; run adr-index.py
$ echo $?
1
```

`INDEX.md` is always written with UTF-8 and `\n` line ends. `--check` reads it as text, so a checkout that turned
the line ends into CRLF still compares equal.

As a pre-commit hook, the hook runs from the root of your repository:

```yaml
repos:
  - repo: <URL of this repository>
    rev: <tag or commit>
    hooks:
      - id: adr-index
```

## Shared code

The script is one file. The code it shares with `adr-check` (the ADR+ header reader and the ADR parser) is
copied into both between `# --- shed:shared NAME begin ---` and `# --- shed:shared NAME end ---` lines; a check
in this repository (`scripts/check-twins.py`) fails if the two copies of a block differ by a byte. The `adrplus`
block holds the reader and schema validator of adr-plus 0.1.0, and the schema as a string constant. Edit a shared
block in both files together.

## Tests

`python3 adr-index.py --self-test` builds its own ADRs in temporary directories, so there are no fixtures to
carry. Red arms prove the guards: a missing index must fail `--check`; an ADR whose status, kind or built word
changed must make the index stale; no decisions folder must exit 2; a run below the root must not find the
decisions folder of a folder above it. The cases that run `adr-index.py` as a command (the default root, the
parent-folder case) use `sys.executable`, so they work wherever Python does.

## Behaviour changes from the source

- The generated `INDEX.md` header no longer names a project: its second line now reads "Generated by
  `adr-index.py` from the ADRs themselves." A project with an existing index runs `adr-index.py` once to
  regenerate it; `--check` calls the old header stale.
- The ADR+ header reader (adr-plus 0.1.0) is part of the script, not imported from a folder beside it. When the
  project has its own `adr-plus.schema.json` in the decisions folder `adr-check` uses that; `adr-index` does not
  read a schema.
- `INDEX.md` is written with an explicit UTF-8 encoding and `\n` line ends on every platform.
- The self-test prints one `PASS` or `FAIL` line per case and a verdict line, in place of one "self-test passed"
  line.
